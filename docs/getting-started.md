# 新手教程：第一次使用 Ailuren-scriptwriter-3act-15beats

这个 skill 不是让你填写复杂表格，而是把你已经有的零散想法整理成能继续拍摄或写作的结构。你可以从一句话、一张画面，甚至一个结局开始。

## 1. Codex 一键安装（推荐）

在新的 Codex 对话中，复制并发送下面这段。这里调用的是 Codex 自带的 `skill-installer`，它会从公开 GitHub 仓库读取根目录的 `SKILL.md` 和 `references/`，并安装到 Codex 的 skills 目录：

```text
$skill-installer

请从这个公开 GitHub 仓库安装 Codex skill：
https://github.com/Ai-luren/Ailuren-scriptwriter-3act-15beats

请安装仓库根目录的 skill，安装名使用：Ailuren-scriptwriter-3act-15beats
安装完成后告诉我安装路径。
```

安装器完成后，重新开一个 Codex 对话，输入下面这句测试：

```text
$Ailuren-scriptwriter-3act-15beats

我想写一个关于“重新相信别人”的 3 分钟短片。
请先只输出 50–100 字故事梗概、为什么值得看、最大风险和 3 个可选方向，暂时不要展开完整 15 Beats。
```

> 如果当前 Codex 会话没有识别到新 skill，重新开一个对话即可。安装器默认不覆盖已经存在的同名 skill；如果提示目标目录已存在，先确认是否已经安装过。

## 2. 手动安装（备用）

在终端进入这个仓库目录，执行：

```bash
mkdir -p ~/.codex/skills/Ailuren-scriptwriter-3act-15beats/references
cp SKILL.md ~/.codex/skills/Ailuren-scriptwriter-3act-15beats/
cp references/*.md ~/.codex/skills/Ailuren-scriptwriter-3act-15beats/references/
```

需要一起复制的是：

- `SKILL.md`：告诉 Codex 什么时候使用、按什么流程创作。
- `references/*.md`：包含 15 Beats 定义、新手模式、品牌资料读取、故事兴趣审核、完播互动审核和默认交付模板。

`examples/` 中的 `.md` 是文本案例，`assets/examples/` 中的 `.png` 是结构图与分镜图；它们是学习参考，不影响 skill 的基本运行。

## 3. 最简单的调用方式

新开一个 Codex 对话，先调用 skill，再说你的想法：

```text
$Ailuren-scriptwriter-3act-15beats

我想写一个关于“记忆应该被分享”的短片。
主角是一位独居老人，手里有一枚记录亡妻歌声的记忆芯片。
请先只输出：
1. 50–100 字故事梗概
2. 为什么值得看
3. 当前最大风险
4. 三个不同的钩子、冲突或结局方向
不要先写完整结构和对白。
```

选定方向后，再继续说：

```text
采用方案 2。保留主题、主角和核心创意，展开故事核心、人物弧光、三幕式、15 Beats 和场景级剧情大纲。
```

结构确认以后，再继续说：

```text
保留这版人物弧光和结局，把场景大纲扩写成正式剧本。
每个场景标注内/外景、地点、时间、动作、必要对白和场景转折。
```

## 4. 你可以提供哪些信息

不需要一次提供全部资料。以下任意一项都可以作为起点：

| 你手里有什么 | 你可以怎么说 |
| --- | --- |
| 一个主题 | “我想讲一个关于重新相信别人的故事。” |
| 一个主角 | “主角是一个怕麻烦的外卖骑手。” |
| 一个画面 | “暴雨夜，旧楼楼顶传来猫叫。” |
| 一个产品 | “要拍一支轻薄笔记本 TVC，重点是移动办公。” |
| 一个结局 | “最后他救了猫，也接受了邻居的帮助。” |
| 一段散乱剧情 | 直接粘贴，并说“请帮我找出结构问题并重组。” |

如果关键信息缺失，skill 会先按最合理方向推进，最后把新增的关键设定列在“创作假设”里。

## 5. 看懂输出

建议按这个顺序检查：

1. **故事梗概**：50–100 字是否已经说清主角、目标、阻碍、代价和独特看点。
2. **为什么值得看 / 最大风险**：是否知道观众会追问什么，以及最可能变俗的地方。
3. **人物弧光**：主角最后的选择是否证明他和开场时不同。
4. **三幕式**：第一幕是否真正启动故事，第二幕是否持续升级，第三幕是否有主动解决。
5. **15 Beats**：中点是否改变规则，一切尽失是否是真正低谷，结尾是否呼应开场。
6. **场景大纲**：每个场景是否改变目标、关系、信息、风险或决定。

## 6. 不满意时怎样修改

用“保留什么 + 修改什么 + 重新输出什么”的方式最容易得到稳定结果：

```text
保留主角、主题和结局。
把第二幕写得更紧张，让主角在中点得到希望，随后因为自己的错误失去更重要的东西。
只重写 15 Beats 和场景大纲，不要改第一幕的人物设定。
```

也可以要求它做诊断：

```text
请不要重写，先诊断这个故事为什么中段松散、All Is Lost 不够低。
按“问题 / 原因 / 最小修改建议”输出。
```

## 7. 适配 AI 视频和 TVC

如果要继续做 AI 视频，补充时长、媒介和画面限制：

```text
这是一个 45 秒 AI 剧情短片。
每个镜头最多一位可见人物，尽量控制在 3 个主要场景；
请让重要转折通过可见动作表达，并在结构确定后再拆成镜头提示词。
```

如果是广告，补充产品、必须出现的卖点和品牌落点：

```text
这是一个 60 秒 TVC。
以下是已确认的品牌 / 产品资料：
（粘贴官方 brief、产品卖点和投稿规则）

请先完整读取资料，区分硬性规范、可选卖点和需要确认的参数；
只选择 1–2 个真正改变人物行动的产品能力，让产品展示服务于剧情，
不要把 15 Beats 机械写成 15 个镜头。
未经品牌方或官方资料确认的“约”“最高”“最长”和性能比较，不要写成绝对承诺。
```

## 8. 常见误区

- 不要把 15 Beats 当成固定的 15 个场景。
- 不要只让角色解释主题，要让最终选择证明主题。
- 不要用突然出现的新能力或新人物解决高潮。
- 不要在结构还没确定时，先花大量篇幅写对白和镜头提示词。
- 做品牌广告时，默认写消费者正在经历的品牌事件，不要把拍广告、参赛、投稿或甲方改稿写成剧情。
- 产品必须通过人物处境、产品能力、关键行动和可见结果形成因果链，不能只在片尾露出。
- 没有官方确认时，优先使用“轻薄、持久、高效、流畅”等非量化表达，并列出需要确认的内容。
