# 输出模板

根据当前任务阶段输出，不要一次性输出所有阶段。

## A. 梗概卡：新故事默认格式

```markdown
### 故事梗概（约 50–100 字）
当【具体处境】发生时，【主角】必须在【限制】内完成【目标】，但【核心阻力】让他/她不得不选择【两难或代价】；随着【独特转折】，观众会发现【结局方向】。

### 为什么值得看
一句话说明观众会追问什么，或会获得什么情绪 / 视觉回报。

### 最大风险
指出最可能变俗、变平、难拍或产品跑题的地方。
```

品牌内容在梗概卡后增加：

```markdown
### 品牌 brief 读取确认
- 已读取：文件名 / 读取范围
- 主题与硬约束：……
- 本故事选用的产品能力：……
- 产品如何改变人物行动：……
- 本次不使用的参数：……
- 需要品牌方或官方规则确认：……
```

用户未确认前，不展开完整三幕式；用户明确要求“一次生成全部”时，可以继续输出后续部分。

## A1. 品牌 TVC 成片：用户说“写一个广告 / TVC”时使用

品牌 TVC 默认指面向消费者的品牌广告成片，不是广告制作幕后。除非用户明确要求创作者、片场、甲方、赶稿或比赛过程，否则不得把这些内容写成主线。

```markdown
### 品牌创意
- 片名 / 核心概念：……
- 前 3 秒事件：……
- 消费者主角：……
- 他现在必须完成：……
- 核心阻力与代价：……

### 30–60 秒成片脚本
按时间段写画面、动作、必要对白 / 旁白、产品可见动作和转折。

### 产品因果
人物处境 → 产品能力 → 关键行动 → 可见结果 → 品牌命题

### 品牌收束
- 产品露出：……
- 片尾文案 / 口号：……
- 需要品牌方或官方规则确认：……
```

品牌 TVC 不要求先让用户确认 50–100 字梗概；如果用户已经明确要求成片，直接交付完整广告方案。不要把“主角使用电脑完成一支广告”当作品牌因果，那是广告制作过程。

## B. 故事结构：用户确认梗概后

### 1. 故事核心

- Logline：主角 + 目标 + 阻力 + 代价 + 独特看点
- 主题命题：由人物选择验证，而不是口号
- 类型、时长、媒介、主平台

### 2. 故事发动机与人物弧光

- 主角：外在目标、内在需求、错误认知、风险
- 关键关系：各自想要什么，为什么不能完全合作
- 人物弧光：初始状态 → 压力 → 旧方法失效 → 新认识 → 困难选择 → 结局

### 3. 三幕式

#### 第一幕｜建立

用具体事件建立人物、欲望、关系和规则；催化事件打破原状态；主角主动进入不可逆行动。

#### 第二幕｜对抗

通过行动展示故事核心卖点；每次失败改变目标、代价、信息、关系、规则或主动性；中点重新定义问题；最低点造成不可轻易恢复的损失。

#### 第三幕｜解决

主角从前文信息、主题或关系中找到答案；通过困难选择解决外部冲突；结尾画面与开场形成有意义的呼应或反差。

### 4. 15 Beats

只在用户需要结构时读取 `beat-sheet.md`。每个 Beat 写：发生什么、改变什么、如何推进下一步；多个 Beat 可以合并在一个场景或视觉段落里。

### 5. 场景大纲

每个重要场景写清：

- 场景编号、地点、时间、内外景；
- 可见动作和人物目标；
- 阻力、选择或信息变化；
- 场景转折；
- 与下一场的因果关系。

## C. 完整剧本

用户明确要求完整剧本时，继续补充：

- 场景编号；
- 内 / 外景、地点、时间；
- 动作描述；
- 角色行为与必要对白；
- 场景转折；
- 声音、画面和转场信息。

不得在扩写时擅自更换已确认的核心故事。

## D. 审查

只在相关任务触发时输出：

- 故事兴趣审核：钩子、冲突、升级、反转、主动性、视觉独特性、模板感；
- 完播互动审核：前 3 秒、前 10 秒、留存节点、评论和转发理由；
- 产品因果审核：人物处境 → 产品能力 → 关键行动 → 剧情改变 → 主题落点；
- 品牌合规审核：产品结构、Logo、竞品、版权、参数和投稿要求。

每项给具体证据。核心钩子、冲突、反转或产品因果低于 4 分时，先给修复方向，不直接润色全文。

## E. 创作假设

只列出为补齐因果而新增的关键设定，并区分：

- 已由用户提供；
- 由品牌资料确认；
- 本次创作假设；
- 需要品牌方或官方规则确认。
